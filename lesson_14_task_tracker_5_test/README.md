# Методичка: планировщик задач на FastAPI и SQLite

Это небольшой fullstack-проект. Пользователь работает со страницей в браузере,
JavaScript отправляет HTTP-запросы, FastAPI обрабатывает их, а SQLite сохраняет
задачи в файл `backend/tasks.db`.

```text
index.html + script.js
          ↓ fetch
        FastAPI
          ↓ SQL
         SQLite
          ↓
 backend/tasks.db
```

## 1. Структура проекта

```text
lesson_14_task_tracker_5_test/
├── backend/
│   ├── main.py          # FastAPI-приложение и SQL-запросы
│   └── tasks.db         # создаётся автоматически при первом запуске
├── index.html           # разметка страницы
├── style.css            # внешний вид страницы
├── script.js            # запросы к API и отрисовка задач
├── requirements.txt     # прямые Python-зависимости проекта
└── README.md            # эта методичка
```

Файл `tasks.db` не нужно создавать вручную. Backend создаст его и таблицу
`tasks`, когда сервер запустится впервые.

## 2. Какие зависимости установлены

В `requirements.txt` находятся две прямые зависимости:

```text
fastapi>=0.115,<1.0
uvicorn[standard]>=0.30,<1.0
```

Они были установлены глобально командой:

```bash
python3 -m pip install -r requirements.txt
```

### FastAPI

`FastAPI` — веб-фреймворк, который:

- связывает URL и HTTP-методы с функциями Python;
- получает и проверяет JSON из запросов;
- преобразует словари и списки Python в JSON-ответы;
- формирует HTTP-ошибки;
- автоматически создаёт документацию Swagger.

В момент установки использовалась версия `0.141.1`.

### Uvicorn

`Uvicorn` — ASGI-сервер. Сам файл `main.py` не слушает сетевой порт. Uvicorn
запускает FastAPI-приложение, принимает HTTP-запросы на порту `8000` и передаёт
их нужным функциям.

В момент установки использовалась версия `0.54.0`.

Запись `uvicorn[standard]` устанавливает Uvicorn с рекомендуемыми дополнениями:

- `uvloop` — быстрый цикл обработки асинхронных операций;
- `httptools` — быстрый разбор HTTP;
- `watchfiles` — отслеживание изменений для режима `--reload`;
- `websockets` — поддержка WebSocket;
- `python-dotenv` — чтение настроек из `.env`;
- `PyYAML` — работа с конфигурацией в YAML.

### Автоматически установленные зависимости

`pip` также установил библиотеки, от которых зависят FastAPI и Uvicorn:

- `Starlette` — низкоуровневая веб-основа FastAPI и middleware;
- `Pydantic` и `pydantic-core` — проверка и преобразование входных данных;
- `AnyIO` — общий слой для асинхронного ввода-вывода;
- `Click` — обработка командной строки Uvicorn;
- `h11` — реализация протокола HTTP/1.1;
- `typing-extensions`, `typing-inspection`, `annotated-types`, `annotated-doc` —
  поддержка аннотаций типов;
- `exceptiongroup` и `idna` — служебные зависимости асинхронного и сетевого
  стека.

Эти пакеты не нужно отдельно записывать в `requirements.txt`: подходящие версии
для них выбирают FastAPI и Uvicorn.

### Почему SQLite не устанавливался

`sqlite3` входит в стандартную библиотеку Python. Отдельный сервер базы данных и
команда `pip install sqlite3` не нужны. Вся база хранится в одном локальном файле.

## 3. Как запустить проект

Для работы нужны два одновременно запущенных процесса: backend и frontend.

### Терминал 1 — backend

Перейдите в папку backend и запустите Uvicorn:

```bash
cd lesson_14_task_tracker_5_test/backend
python3 -m uvicorn main:app --reload
```

Значение `main:app` читается так:

- `main` — файл `main.py`;
- `app` — созданный внутри него объект `FastAPI`.

Флаг `--reload` перезапускает сервер после сохранения изменений в Python-коде.
Он удобен при разработке, но не применяется на боевом сервере.

После запуска доступны:

- API: <http://127.0.0.1:8000/api/tasks>;
- Swagger UI: <http://127.0.0.1:8000/docs>;
- альтернативная документация ReDoc: <http://127.0.0.1:8000/redoc>.

### Терминал 2 — frontend

Вернитесь в корень проекта и запустите простой статический сервер:

```bash
cd lesson_14_task_tracker_5_test
python3 -m http.server 5500 --bind 127.0.0.1
```

Откройте в браузере:

<http://127.0.0.1:5500>

Вместо `http.server` можно использовать расширение Live Server для VS Code, но
оно должно работать на порту `5500`, потому что этот адрес разрешён в CORS.

Чтобы остановить любой из серверов, нажмите `Ctrl+C` в соответствующем терминале.

## 4. Как устроена база данных

При старте приложения функция `create_tables()` выполняет запрос:

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    is_complete INTEGER NOT NULL DEFAULT 0
);
```

| Колонка | Назначение |
|---|---|
| `id` | Уникальный номер, который SQLite назначает автоматически |
| `title` | Текст задачи; пустое значение запрещено |
| `is_complete` | Состояние задачи: `0` — не выполнена, `1` — выполнена |

SQLite сохраняет изменения в `backend/tasks.db`. Поэтому задачи остаются после
обновления страницы и перезапуска серверов.

## 5. Как работает backend

### Запуск приложения

Uvicorn импортирует `app` из `main.py`. FastAPI запускает функцию `lifespan()`,
а та вызывает `create_tables()`. После подготовки базы сервер начинает принимать
запросы.

Для каждого обращения к базе `get_connection()` открывает соединение. Выражение
`with get_connection() as connection` фиксирует успешные изменения и завершает
работу с соединением после выполнения запроса.

### Модели Pydantic

Backend принимает два вида JSON:

```python
class TaskCreate(BaseModel):
    title: str

class TaskStatusUpdate(BaseModel):
    is_complete: bool
```

Если клиент передаст данные неправильного типа или пропустит обязательное поле,
FastAPI вернёт ошибку валидации `422` до выполнения SQL-запроса.

### Маршруты API

| Метод | URL | Действие | Успешный статус |
|---|---|---|---|
| `GET` | `/api/tasks` | Получить все задачи | `200 OK` |
| `POST` | `/api/tasks` | Создать задачу | `201 Created` |
| `PATCH` | `/api/tasks/{id}` | Изменить статус | `200 OK` |
| `DELETE` | `/api/tasks/{id}` | Удалить задачу | `204 No Content` |

#### Получение задач

```http
GET /api/tasks
```

Backend выполняет `SELECT * FROM tasks ORDER BY id` и возвращает массив:

```json
[
  {
    "id": 1,
    "title": "Выучить FastAPI",
    "is_complete": false
  }
]
```

#### Создание задачи

```http
POST /api/tasks
Content-Type: application/json

{
  "title": "Выучить FastAPI"
}
```

Backend удаляет пробелы по краям, проверяет непустое название, выполняет `INSERT`
и возвращает созданную задачу. `id` назначается SQLite, а не JavaScript.

#### Изменение статуса

```http
PATCH /api/tasks/1
Content-Type: application/json

{
  "is_complete": true
}
```

Backend выполняет `UPDATE`. Если задачи с таким `id` нет, возвращается
`404 Not Found`.

#### Удаление задачи

```http
DELETE /api/tasks/1
```

Backend выполняет `DELETE`. Успешный ответ имеет статус `204` и не содержит JSON.

### Зачем нужен CORS

Для браузера адреса `127.0.0.1:5500` и `127.0.0.1:8000` имеют разные origin,
потому что отличаются порты. Без `CORSMiddleware` браузер заблокировал бы запросы
frontend к backend. Сервер разрешает запросы только от:

```text
http://127.0.0.1:5500
http://localhost:5500
```

## 6. Как работает frontend

### HTML и CSS

`index.html` содержит поле ввода, кнопку добавления, пустой список задач и блок
статистики. `style.css` оформляет карточку, строки задач, кнопки и зачёркивание
выполненной задачи.

HTML не хранит задачи. Все элементы `<li>` создаются JavaScript во время работы.

### Локальный массив

В `script.js` есть массив:

```javascript
let tasks = [];
```

Он является только временной копией для отрисовки. Источник истины — SQLite.
После обновления страницы массив снова пуст, а затем заполняется данными из API.

### Первоначальная загрузка

В конце файла вызывается `load_tasks()`. Функция отправляет `GET /api/tasks`,
преобразует JSON в массив JavaScript и вызывает:

- `render_tasks()` — создаёт checkbox, текст и кнопку для каждой задачи;
- `render_stats()` — считает число выполненных задач.

### Добавление

Кнопка вызывает `add_task_button_click()`. Функция:

1. читает и очищает от пробелов значение поля;
2. не отправляет пустое название;
3. выполняет `POST /api/tasks` с JSON;
4. очищает поле после успешного ответа;
5. снова вызывает `load_tasks()`.

### Изменение checkbox

При изменении checkbox функция `change_status_checkbox_click()` отправляет
`PATCH /api/tasks/{id}`. В JSON передаётся актуальное значение `checkbox.checked`.
После ответа список снова загружается из базы.

### Удаление

Кнопка «Удалить» вызывает `delete_task_button_click(id)`, которая отправляет
`DELETE /api/tasks/{id}` и после успеха заново загружает список.

### Обработка ошибок

Каждый сетевой запрос находится внутри `try...catch`. Свойство `response.ok`
проверяет успешность HTTP-ответа. Если backend недоступен или вернул ошибку,
сообщение показывается в блоке статистики и записывается в консоль браузера.

## 7. Полный путь одного действия

Например, пользователь отмечает задачу выполненной:

```text
checkbox в браузере
        ↓ change event
change_status_checkbox_click(id, true)
        ↓ fetch PATCH
FastAPI: change_task_status()
        ↓ SQL UPDATE
SQLite: tasks.db
        ↓ HTTP JSON-ответ
load_tasks()
        ↓ GET /api/tasks
render_tasks() + render_stats()
        ↓
обновлённая страница
```

После любого изменения frontend повторно запрашивает список у backend. Благодаря
этому интерфейс всегда отображает фактическое состояние базы данных.

## 8. Проверка через Swagger

Откройте <http://127.0.0.1:8000/docs>. Для любого маршрута можно нажать
`Try it out`, заполнить данные и затем `Execute`. Это позволяет проверить backend
отдельно от frontend и увидеть URL, тело запроса, статус и JSON-ответ.

## 9. Частые ошибки

### `ModuleNotFoundError: No module named 'fastapi'`

Зависимости установлены не в тот Python. Проверьте интерпретатор и повторите
установку через него:

```bash
which python3
python3 -m pip install -r requirements.txt
```

### Страница открылась, но задачи не загружаются

Проверьте, что backend продолжает работать на порту `8000`, а frontend открыт
именно через `http://127.0.0.1:5500`, а не как локальный файл `file://...`.

### Порт уже занят

Завершите ранее запущенный сервер сочетанием `Ctrl+C`. Для проекта лучше
сохранить порты `5500` и `8000`, иначе потребуется изменить `API_URL` и CORS.

### Как очистить все задачи

Остановите backend и удалите файл `backend/tasks.db`. При следующем запуске он
будет создан заново. Это полностью удаляет сохранённые задачи.
